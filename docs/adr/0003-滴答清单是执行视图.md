# 滴答清单是执行视图，markdown 只留"为什么"

> **Status**: superseded by [ADR-0004](0004-四清单取代单清单.md)（2026-11-03）。
> 「不做 GTD 四清单」一条被推翻；本文件其余条款继续有效，逐条清单见 0004 的「后果」节。

## 决定

任务的时间、优先级、完成状态只在滴答清单里维护，不再回写计划文档。计划文档、`docs/adr/` 这类地方只记录判断依据、验收清单、备忘模板——手机不需要读的东西。

## 理由

两处同步必然漂移，漂移之后两边都不再可信。而这两类信息的读者不同：手机上要的是"现在干什么"，文档里要的是"当初为什么这么定"。

## 后果

- 执行视图：滴答清单里时间、优先级、完成状态各有其位——**父级条目 = 一件事**，只带截止日、优先级、一句备注（"什么时候必须完"）；**下一级条目 = 一个动作**，各自带开始/截止时间（"什么时候做什么"）。
- 不用 checklist 项承载动作：checklist 没有时间字段，只能当纯勾选清单。
- 用 `dida` CLI 批量写时有两个坑：`--items '[]'` 清空会间歇报 500；把 `dida` 调用放进 PowerShell `foreach` 会触发 libuv 断言崩溃。**逐条显式调用即可**。
- 周结束时，把滴答的完成情况誊回计划文档一次，或直接丢弃逐日表、只留决策。
- 不做 GTD 四清单（项目/执行/等待/待办日历）与清单的分层映射。试过一轮，同一件事会在四个清单各出现一次；在无人维护的情况下，分层本身就是负担。**（本条已被 [ADR-0004](0004-四清单取代单清单.md) 推翻。）**
- 不使用类型标签。优先级加截止日已经够表达，再加标签会稀释。**（本条已被 [ADR-0005](0005-时间档降为标签.md) 推翻。）**
