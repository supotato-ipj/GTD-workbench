# 工作台是焦点引导器：六箱全景降为下钻层

> **Status**: accepted（2026-11-07）· supersedes [ADR-0007](0007-画布结构六箱一天轴.md) · 修订 [ADR-0012](0012-焦点视图是像素工位.md) 中「预计耗时」一条（2026-11-08）

## 背景

现在的工作台是**六箱全景画布**（[ADR-0007](0007-画布结构六箱一天轴.md)）：六个纸箱对应 GTD 的六个容器，箱内按「今天／明天／本周／以后」的天刻度堆叠便贴，另有本周主攻带、已沉底区和规则角标。

它能回答"一件东西落在哪个容器"，回答不了"**我现在该做哪一件**"——而 GTD 的目的恰恰是"明确知道下一步应该做什么"。

三个结构性原因：

1. **滴答按容器组织，不按时间组织。** 打开工作台要先横看六个箱子、再纵向读时间轴，最后自己在脑子里把"期限 × 时间档 × 今天还剩多少时间"合成一个决定。这一步合成没有任何机制承担。
2. **画布是均质的。** 所有便贴同一个组件、同一套字号，六个纸箱同宽；优先级只在右上角显示一个小数字，而且从不参与排序。视觉重心因此不落在任何一件事上。
3. **工作容量不在画面里。** 一天能装多少、现在还剩多少、这一件要多久——这些数字在另一份文档里，画布一个字都没有。所以"装不装得下"无从判断。

结果是：一块看起来完整、测试全绿、但**形态不对**的画布。它不是缺功能，是把"分类"当成了主信息。它已被判定为形态问题而停用，所以这次不是迭代，是换形态。

## 决定

**工作台的默认形态是焦点引导器：默认只回答一件事——现在该做哪一件。**

面板自上而下四层：

1. **顶部常驻**——今日日清状态（几笔未还）与今日剩余可排时间。它不进排序、不抢主卡，只是背景上一直亮着的几个数。
2. **一张行动卡（主位）**——一条动作，四样必备：工作内容、完成时限、完成要求、预计耗时；外加一句容量提示。卡面上有两个写口：**完成**、**改期**；另有一个零写入的**跳过**。
3. **「接下来」2–4 条**——窄条，只写标题与时限。它回答"今天还剩多少"，并让人能换手。
4. **六箱下钻层**——默认不可见。点开后是 v1 的六箱画布原样：纸箱、便贴、箱签、已沉底、规则角标全部保留。

配套的三条边界：

- **六箱全景不删除**，降为下钻层。分类从"主信息"退成"内部键"：往六个容器丢东西这件事照旧，工作台替你算出该拿哪一件。
- **判定仍然在会话里由 agent 承担**，工作台不承担判定（承接 [ADR-0006](0006-工作台是只读视图.md)）。
- **写口只有两个**（完成、改期），走与读取同一条 HTTP 契约；「跳过」是纯视图状态，零写入。

焦点怎么选：先过**资格**（来自 GTD 明晰流程图），再按 **GTD 选择行动四标准**排序。规则本身写在 [ADR-0010](0010-焦点资格与排序.md)，容量参数的来路写在 [ADR-0011](0011-容量参数的初始化与调校.md)。

## 理由

- **GTD 的目的是明确下一步。** 一块按容器分类的画布，回答的是"东西落在哪"，不是"现在干什么"。分类是 GTD 的中间步骤，不是目的。
- **保留全景而不是删掉它。** 全景仍有真实用途：看清一件东西落在哪、哪个容器在积压、项目级失速在哪被漏掉。删掉它等于因为一次形态判断而丢掉已验证的能力（便贴、箱签、已沉底、规则角标）。降为下钻层，代价只是多点一次。
- **默认视野必须是窄的。** 视觉重心不落在任何一件事上的根因是版面均质；把视野收成"一张卡 + 几条窄条 + 一个入口"，重心才有地方落。
- **容量必须进画面。** "这一件装不装得下"是"现在该做哪一件"的前半句；不给这个数，卡上的建议就只是排序。
- **写口只开两个。** 焦点引导器要求"做完了"和"现在做不了"能当场发生，否则用户每做一件事都要回会话或滴答再回来，工作台就退回成一个只能看的板子。只开两个，是为了让"工作台会改我的数据"边界清楚。

## 代价

- **v1 画布不再是默认形态**：第一次打开的人需要多点一次才看到六箱，旧的肌肉记忆会失效。
- **默认视野变窄，信息也变少**：周回顾、项目级失速、容器失衡都不在默认视野里，需要下钻或回会话才看得见。
- **焦点推导一旦出错，误导性比全景更高**：全景给出的是一堆平铺的事实，焦点给出的是一个"建议你做这个"的判断。做错了它更显眼，也更可能被照做。因此资格与排序必须是**纯函数、可断言**，与渲染完全分离（见 [ADR-0010](0010-焦点资格与排序.md)）。
- **容量数字进主界面后，参数不准就直接误导**：顶部那个"还剩 X 小时"是工作台说的最肯定的一句话，而它的准确性取决于用户多久没校准参数。缓解手段与残余风险见 [ADR-0011](0011-容量参数的初始化与调校.md)。
- **写口带来同步面**：工作台不再纯粹只读（[ADR-0006](0006-工作台是只读视图.md) 的修订节），写失败必须显式呈现，且失败时主卡不得消失。
- **形态变更本身有返工成本**：观感类改动测试测不出来，"测试全绿"不等于"形态对"。因此观感先行：用一次性的假数据原型确认观感，原型不接真实快照、不进主线，确认后再接。

## 修订（2026-11-08）

「决定」第 2 条里那张行动卡的**四样必备**减为三样：

- **卡上留**：工作内容、完成时限（一枚标签）、完成要求。
- **「预计耗时」移出卡面**，与「装不装得下」「今天还剩多少可排时间」一起放到工位桌左的小电子屏上（[ADR-0012](0012-焦点视图是像素工位.md)）。
- 理由：卡改成竖版之后只有 200×280 美术像素，四样必备加两个写口会把一张卡撑成一页表格；而"装不装得下"本来就是环境读数，不是一个动作的内容。**一个数仍然只出现一次**——耗时与容量判定现在只在小屏上。
- 主位、两个写口、零写入的「跳过」、下钻层这些不变。
