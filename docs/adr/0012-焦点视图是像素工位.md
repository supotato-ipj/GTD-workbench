# 焦点视图是像素工位：桌面、台灯、一张被照亮的卡

> **Status**: accepted（2026-11-08）· 修订 [ADR-0007](0007-画布结构六箱一天轴.md) 中「质感」一条在焦点视图范围内的适用

## 背景

[ADR-0009](0009-工作台是焦点引导器.md) 把工作台从六箱全景改成焦点引导器之后，焦点视图仍是一块**铺满主区的深色面板**：主卡占据整个窗口宽度，与下面「接下来」的窄条共用同一套边框、底色和排法。它读起来是「一个区块加几行表格」，不是一张卡。

用户的判断是：**铺满窗口的卡在比例上就不是卡，是页面**。缺的不是装饰，是**参照系**——没有桌面、没有光源、桌上没有别的东西，"这张卡有多大"就没有依据，卡只能跟着窗口长。

## 决定

**焦点视图是一个工位：一张桌面，一盏台灯，灯光照在桌面上，行动卡平放在桌面上，是画面里唯一被照亮的主体。**

八条边界：

1. **视角与构图。** 微俯视角（略高于桌面，看得见桌沿与前缘）；桌面占画面下部约三分之二，上方是暗房间；卡宽约为桌面宽的 55%，左右各留至少 15% 桌面；桌面上的道具取克制的标准工位——台灯、**熄屏**显示器（只作剪影）、笔筒、杯子、垫板。
2. **光只负责照明。** 台灯是纯氛围，不承载任何读数——不表示剩余时间、不表示深度名额、不表示"该看哪一张"。光开始表示时间的那一刻，台灯就变成一根斜着的进度条。
3. **场景自带调色板，只有一套。** 夜色 + 暖光 + 卡的纸色，脱离宿主 `--dsw-alias-*` 令牌，不随明暗主题切换（不做白天版）。ADR-0007「质感」里"不换配色"在焦点视图范围内被取代。
4. **文字全点阵。** Fusion Pixel 12px 为默认，Ark Pixel 12px 兜底，仍缺的字逐字回退系统字体。字号只有 12 与 24 两个美术像素台阶，层级靠明暗、描边、留白承担。ADR-0007「质感」里"不换字体"同样在焦点视图范围内被取代，且它当初的理由（中文手写体在 Windows 上常常找不到、最后回退成难看的默认字）已不成立——字体随包自带、由本机路由发出，不依赖系统里装了哪些字。
5. **像素网格整数倍缩放。** 一个美术像素等于 k 个设备像素（k 取整数，先 3、放不下降 2），多出来的空间由暗房间延伸填满，不出黑边；字号与网格同倍数，`字号 × devicePixelRatio` 必须落在整数设备像素上。
6. **读数各有桌面实体。** 今日日清＝一叠未还的便签（「容量参数定于某日」「窗口外那笔日清不占可排时间」两行小字收进这叠便签，点开才看见）；深度名额＝灯座上一枚方形指示块；**剩余可排时间不进场景**——卡上已经有「装不装得下 · 还剩 0 分钟」，同一个数不出现两遍。「接下来」＝桌面右侧的立式卡夹，露出标题与时限，点一张抽到主位；等待清单的提醒位＝桌上插着的一面小旗；六箱入口＝桌下的抽屉；标签栏与刷新＝桌沿两块标牌与桌角一枚开关。
7. **卡本身：信息全保留，排法按卡的物理逻辑。** 标题最大；完成时限是卡上一枚标签；完成要求是正文；预计耗时与容量判定缩成卡边小字；卡脚留项目指针。
8. **写口边界不变。** 左右划**只换卡、零写入**；完成与改期仍是卡面两枚按钮，仍是仅有的两个写口（[ADR-0006](0006-工作台是只读视图.md) 不变）；跳过＝把卡插回卡夹末尾。按下完成或改期后：盖一枚像素印章、停半拍、卡被抽走、卡夹里下一张滑上来。空态是灯下一张空白卡（写「现在没有该做的事」）；取数失败与未登录是把一张纸条压在卡上。

**工位只是呈现层**：不新增实体、不新增待办；桌上那张卡仍然是行动卡。**六箱画布不在此列**：它保持 v1 的纸感与宿主主题令牌，像素化只发生在焦点视图。

## 理由

- **参照系先于装饰。** "不像卡片"的根因是它铺满窗口；加阴影、加描边都救不了比例。桌面、台灯、卡夹给出的是尺度——卡一旦有了邻居，就不再是页面的一个区块。
- **光的唯一性承担注意力。** 卡是画面里唯一被照亮的东西，这件事不需要任何排序解释；但它也**不能**再表示别的，否则同一个亮度要同时说两件事。
- **像素风是一套网格，不是一层贴图。** 场景、字号、缩放必须共用同一个整数网格；只要有一处落在半像素上，整幅画面的"像素"感就散了。所以缩放取整数倍、字号取 12 的倍数，这两条是硬条件而不是偏好。
- **固定调色板是光的代价。** 要照出光斑，就必须自己掌握明暗；借宿主的背景色照不出光。
- **划动只换卡。** 《王权》式的划动之所以成立，是因为它的选择不可撤销也无所谓对错；滴答里的"完成"改了要回去改，把它绑在一条手指轨迹上代价太高。划动给手感，写入口仍然有形。
- **读数实体化是为了不让顶部变成仪表盘。** 三个数并排一行是最像网页的结构；拆成桌上的几件东西，读数的分量就从"表头"变成"桌上的物件"。

## 代价

- **两套世界当面对撞。** 焦点视图是夜里的像素工位，六箱画布是纸感的网页画布，同一面板里切换会跳一下。这是把像素化限定在焦点视图的直接代价。
- **只有两级字号。** 点阵字只能取 12 的整数倍，卡上的层级比现在粗，只能靠明暗与描边补。
- **离开宿主主题。** 宿主切到亮色主题时，焦点视图仍然是夜色；它与面板里其他部分可能不协调。这是决定 3 的直接代价。
- **字体体积与缺字。** 约 600 KB 的点阵字体（连同 OFL 许可文本）随包进仓库；生僻字仍会冒出非像素的系统字。
- **DPR 敏感。** Windows 125%／150% 缩放下，字号与网格没对齐到整数设备像素，字就会糊；这条只能靠实现时按 DPR 取整来保证。
- **观感仍然测不出来。** 测试全绿不等于形态对；这次同样先出一次性假数据原型过观感门禁，确认之后再接真实快照。

## 修订（2026-11-08）

观感门禁之后的四处修正，前两条推翻本文原决定：

1. **卡是竖版、立在桌面上。** 平放的一张横卡在微俯视角下读起来仍是"页面里的一个区块"；改成竖版卡立在桌面上（200×280 美术像素，约 1:1.4），底部有桌面上的投影，卡面左缘被灯照亮一档。决定 1 里的"卡宽约为桌面宽的 55%"随之作废——竖版卡按**高宽比**定，不再按桌宽占比定。
2. **剩余可排时间进场景。** 原决定 6 写的"剩余可排时间不进场景，因为卡上已经有『装不装得下』"被推翻：卡上不再写耗时与容量之后，这个数就没有落点了。现在它和「预计耗时」「装不装得下」一起放在**桌左的小电子屏**上（`11-08 周六 / 预计 40 分钟 / 装不下 / 可排 0 分钟`）。"一个数只出现一次"这条规则仍然成立——它只在小屏上出现。
3. **卡上只留完成时限那一枚标签**，不再与屏幕重复；原决定 7 里"预计耗时与容量判定缩成卡边小字"改为"移到小屏"。
4. **桌面抬到画面下方约三分之二**（原决定 1 是"约三分之二"，这次把它落实到 250/420 美术像素）；今日日清的便签叠压在卡夹下方，与卡夹同列。
5. 台灯的灯罩改为向下张开的锥形，罩口一圈暖色——原来那版是几条横条，读不成灯。

代价追加：**"装不装得下"不再在卡面上**，判断时要偏头看桌左小屏；竖版卡窄（内宽 180 美术像素），长标题折到第四行就会顶到按钮，实施时必须定一条截断或缩排的规约。

## 补记（2026-11-08 实施）

决定 2 说"台灯不承载任何读数"，决定 6 说"深度名额＝灯座上一枚方形指示块"，这两条在实施时按**同时成立**来读：

- **光本身不表示任何读数**——不表示剩余时间、不表示深度名额、不表示该看哪一张；
- 灯座上那枚指示块是**一件独立的桌面物件**（用掉就熄灭），不是灯光的一部分。

工位里没有任何一处亮度被用来编码数字；台灯只是照明。
