# 焦点资格与排序：资格是过滤，排序是四标准映射

> **Status**: accepted（2026-11-07）· 配套 [ADR-0009](0009-工作台是焦点引导器.md)

## 背景

工作台改成焦点引导器之后，主位只有一张卡。要让"为什么是这一件"这件事可解释、可复现、可断言，得先回答两个问题：

1. **谁有资格上卡？**
2. **多个候选都合格时，按什么排？**

规则散着说会漂；把资格和排序揉成一个打分，就没法分别回答"这条为什么没上卡"和"这条为什么排第一"，也没法测。

现成的依据有两处：**GTD 明晰流程图**给出"什么已经算处理完了、什么还在收集箱"，**GTD 选择行动四标准**（情境、可用时间、精力、优先级）给出"多个可做的东西怎么挑"。

## 决定

### 一、焦点资格（过滤，不是排序）

只有下列动作有资格进入焦点。资格是**过滤**：一条动作要么在候选集里，要么不在；不合格的不参与后面的排序，也不占位。

1. 已明晰、落在**执行清单**的动作。
2. **日历**项仅在它那一个时刻进入焦点（外部约定时刻已到或即将到）。
3. **等待清单**永不占主卡；仅在「什么时候回」已过、即「到期没回」时以提醒形式出现。
4. **项目清单**不出卡，只作为卡脚指针与下钻入口。
5. **可能清单**不出卡，到**触碰日**才进入焦点。
6. **日清**不参与排序（见下一节），但常驻顶部。
7. **收集箱**里未判定的捕获不进焦点——**唯一例外是两分钟规则**：能在两分钟内做完的捕获直接顶到主卡位，且仅在整理收集箱（日回顾窗口或收集箱非空）时允许；深度块进行中不允许两分钟卡抢位。
8. 缺时间档的动作视为**未判定**，不进焦点。

每条动作都要能说出自己落在哪一条：不合格的动作带一个**不合格原因**（未判定／等待／收集箱未明晰／未来日历项……），供下钻层显示。

### 二、焦点排序（GTD 选择行动四标准）

| GTD 四标准 | 本系统的对应物 |
|---|---|
| 情境 | **时间档**（深度／事务／日清）——取代原 @Context |
| 可用时间 | **当前窗口 + 今日深度配额 + 剩余可排时间** |
| 精力 | **不建模**（无字段、无历史数据，明确不做） |
| 优先级 | 期限与承诺：① 逾期或今天到期 → ② 本周主攻（深度档，且配额未用）→ ③ 本周内到期 → ④ 事务档填充 → ⑤ 其余有期限 |

- **日清不在这条链里**：它不参与优先级排序，作为固定成本在顶部常驻显示，并在其时段到来时进入「接下来」而不抢主卡。
- **优先级字段只做同组内 tiebreaker**，不跨组。原因：实测该字段在中档高度聚集，单独用没有区分力。
- 同组内仍按到期时间升序、再按 id 稳定排序，保证两次请求之间顺序确定。

### 三、时段驱动

主卡按当前所处的时间窗口挑选：连续窗口优先派深度、可打断窗口派事务与日清、日终窗口派必须当天还清的成本。窗口是**默认建议不是锁**：当前时刻落在窗口外（插入损耗、临时离岗、加班）时按实际位置重算，不报错、不空转。

深度配额用完后，后续深度动作自动推到下一天。

## 理由

- **资格与排序必须分开。** 分开之后，"这条没上卡"和"这条排第一"各自有一个可查的答案；揉在一起就成了一个说不清来源的分数，用户看不懂，测试也断言不了。
- **等待清单永不占主卡**：推进权不在使用者身上，等别人的事占着唯一的主位，等于把焦点浪费掉。它只在"到期没回"时以提醒形式出现，正是它唯一需要打扰使用者的时刻。
- **项目不出卡**：卡上写的是下一步行动；项目已经在计划文档里，再拆一次就是重复劳动。把它降为卡脚指针与下钻入口，既保留"它在哪条线上"的信息，又不占主位。
- **可能清单到触碰日才进**：可能清单的定义是"当前不投入、但不想丢失"；提前放上主位等于让不投入的事占着要投入的位置。触碰日是它唯一的正确入口。
- **缺时间档即未判定**：时间档的判据是"眼前这段时间能不能用"（[ADR-0005](0005-时间档降为标签.md)）。没有档位就不知道它能不能用在现在，那它就还没被判定过，不该出现在"现在该做"的答案里。
- **两分钟规则是唯一的口子**：它对应 GTD 里"两分钟能做完就当场做"，但必须限定在整理收集箱的时段、且不许在深度块进行中抢位——否则琐事会把上午唯一的连续块切碎。
- **精力不建模**：没有字段也没有历史数据，猜出来的精力位只会制造假的确定性，而且这种假确定性用户还改不动。
- **优先级字段不跨组**：跨组用会得到"某条明显该在后面的却排前面"的结果；限制在组内做 tiebreaker，既用上了这个字段，又不让它越过有意义的分组边界。
- **稳定排序不可省**：同一批快照两次请求必须给出同一顺序，否则"主卡是谁"会随刷新跳变。

## 代价

- **资格判定需要完整快照**：容器为空、字段缺失的条目会掉出焦点（缺时间档即未判定）。用户可能因此以为"今天没活"——因此不合格原因必须能看到，空候选集必须显示"今天没有够格的动作"，不能画成空板。
- **两分钟规则的边界靠估计**：两分钟是估计值，不是度量。估错了会出现"琐事抢走深度块"，只能靠"深度块进行中不许抢位"这条硬规则兜底。
- **深度配额用完后深度动作被推走**：这是正确行为，但用户看到的是"我今天那件深度活不见了"，文案必须说清它是推到了明天，而不是消失了。
- **组内不跨优先级排序**：同组里仍可能出现"用户心里更重要的那件排在后面"。这是为稳定性与可解释性付的代价。
- **规则是一整套而不是一条**：资格 8 条 + 排序 5 组 + 两个例外，任何一条被改动都会改变主卡是谁。因此资格判定、排序、卡片组装必须是**纯函数**，与渲染完全分离（见 [ADR-0009](0009-工作台是焦点引导器.md) 的模块划分）。
- **时段驱动使结果随时刻变化**：同一批动作在上午和在晚上给出的主卡不同。这是对的，但意味着"主卡是谁"不能作为跨时段的稳定标识来断言，测试要固定当前时刻。
