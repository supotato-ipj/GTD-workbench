# 时间档从清单降为标签：容器只留 GTD，档位靠标签筛

> **Status**: accepted（2026-11-04）· 修订 [ADR-0004](0004-四清单取代单清单.md) 中「不使用类型标签——时间档用清单分层表达，不引入标签维度」一条

## 决定

- 滴答的**清单**只承载 GTD 容器：**项目清单 / 执行清单 / 等待清单 / 待办日历 / 💭可能**，收集箱用滴答 inbox。参考资料的载体是项目页，不建清单。
- `@深度` / `@事务` / `@日清` 三个清单删除，改成同名**标签**：`深度` / `事务` / `日清`，只挂在执行清单的动作上。
- 判据不变：三档问的仍是「眼前这段时间能不能用」。变的是载体——清单是排他的（一条任务只能在一个清单），标签是可叠加的。时间档本来就是动作的属性，不该占一个容器名额。

## 为什么改

ADR-0004 原条款要求「时间档用清单分层表达，不引入标签维度」，实际代价是三条：

1. **容器数对不上**：5 个 GTD 容器 + 3 个时间档清单 = 8 个，嘴上说「四清单」，界面上数不清。
2. **同一件事被问两次**：一条动作要回答「在哪个清单」和「在哪个档」，搬一次动两个字段。
3. **筛不动**：「今天能干的所有事」要在三个清单之间横跳；而滴答的标签筛选是原生的，一个筛选就是今天的工作面。

上一版结构还有第二个病：清单靠名字互相解释（`@深度` 里才看得出来是深度活），过滤、统计、跨天重排都要靠人记名字。

## 代价与守线

- 新增一条不变式：**执行清单里每条动作必须且只能带一个时间档标签**。没标签的动作 = 没判定，日回顾要清掉。这条比「清单分层」更硬——清单分层时漏填清单会落到默认清单，标签漏了就是空的，筛出来立刻看得见。
- 标签名不带 `@`。`@` 是清单名时代的装饰，标签上不加。
- 可能清单的**触碰日**用 dueDate 承载（滴答没有触碰日字段）。批量降级按触碰日逐条设：到点没动就删，不再挂着。
- 项目清单仍然不带子任务；已关闭的子任务是历史，不删也不复用。
