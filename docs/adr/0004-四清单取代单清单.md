# 四清单取代单清单：改回完整 GTD 的容器结构

> **Status**: accepted（2026-11-03）· supersedes [ADR-0003](0003-滴答清单是执行视图.md) 中「不做 GTD 四清单」一条

## 背景

上一版用单清单承载全部工作，四清单试过一轮失败就退回去了。失败的原因不是清单多，是**粒度错了**：把同一个「一件事」抄进了四个容器。

## 决定

按 GTD 脑图重建计划体系：收集箱进，项目 / 执行 / 等待 / 日历四个容器出，外加可能清单与回收箱。判定语言照 GTD 原书的顺序，不照那张图——图的 2 分钟规则排在最后一问、「该我做吗」排在「有特定时间吗」之后、「项目清单」挂在「不能一步搞定」下面（等于先建项目再想下一步），照图实现会绕。

这次用一条更硬的规则代替四清单的否定理由——**一个动作只允许存在一次**。

## 后果

- **容器**：`📥 收集箱` / `🎯 项目` / `▶️ 执行` / `⏳ 等待` / `💭 可能`。执行清单下分 **@深度 / @事务 / @日清** 三档（**2026-11-04 起三档改由标签表达，见 [ADR-0005](0005-时间档降为标签.md)**）。日历只装外部约定时刻（开庭、送达截止、约定的会、回收截止），**期限不是日历条目**。参考资料的载体是项目页，不建清单；回收箱不建，直接删。
- **一个动作只存在一次**：项目清单里的项目**不带子任务**，备注只写「下一步：X」；动作只能出现在执行清单或等待清单，靠备注回指项目。
- **时间档取代 @Context**：@电脑 这类地点维度在本上下文里无效——它覆盖 100% 的工作，筛不掉任何东西。三档的判据是「眼前这段时间能不能用」，不是「手边有什么工具」。
- **等待清单每条必须带四样**：等谁、等什么、什么时候回、到期没回做什么（催 / 降级 / 自己上）。缺第四项的不产生动作，只是让自己感觉 systematic。
- **判定由 agent 承担**：人只口述「这件事是啥、要不要做、卡在哪」，落到哪个容器、写成什么动作、到期没回追谁，由 agent 执行。判据是容器能不能被填满——`执行清单` 和 `等待清单` 长期为 0 条，说明判定根本没发生（实测旧容器的状态：执行 0、等待 0，其余容器堆着未判定条目）。
- **日回顾在开工前的固定时段**（具体时刻属个人配置，不进本仓库）；**周回顾在每周固定时段**，只产出三行：上周未兑现、本周主攻、本周明确不做。项目级失速只能在这里被发现。
- **项目页留在本地文档里**，记为什么、验收标准、变更史；滴答只放标题、截止日、一句指向项目页的备注。ADR-0003 的「markdown 只留为什么」继续有效。
- **可能清单每条必须带触碰日**；没有触碰日的进回收箱。没有触碰日等于被静默放弃。
- **ADR-0003 继续有效的条款**：执行视图是时间/优先级/完成状态的唯一事实来源；不用 checklist 项承载动作；`dida` 的两个坑（`--items '[]'` 间歇报 500、放进 PowerShell `foreach` 触发 libuv 崩溃）；不使用类型标签——时间档用清单分层表达，不引入标签维度（**本条已被 [ADR-0005](0005-时间档降为标签.md) 推翻：时间档改为标签**）。
- **警戒线**：如果两周内开始给项目挂子任务，说明规则没守住，退回 ADR-0003 的单清单结构。

## 为什么这次能成立

上次失败的直接证据是「同一件事会在四个清单各出现一次」。四清单本身不产生复制，粒度才会。真正扣动复制的是「项目」和「动作」没被分开定义——同一件需要多人分工确认的事，同时是项目、又被当成一个动作塞进执行清单、又因为「等同事回意见」出现在等待清单。

现在那个项目只在项目清单出现一次；动作是「发出征询」「汇总反馈」这样的条目，各一次。

## 上次那套容器还在，而且空着

查滴答，上一版的五个清单都还在：执行 0 条、等待 0 条，项目清单里全是「建立机制」类想法，待办日历里全是周期性日常（被当日历用），不可行动清单里参考资料、私事、闲聊混装。

这组状态就是上次失败的死因，也否掉了 ADR-0003 的诊断：失败不是「分层太重」，是**判定环节没发生**。东西一进来就被丢进某个筐，没有一个筐在回答「下一步做什么」，于是两个最关键的筐永远是空的。容器保留，方法补上——这次改的是谁来判定、什么时候判定。
