# 容量参数的初始化与调校：agent 建参数，用户点头才改

> **Status**: accepted（2026-11-07）· 配套 [ADR-0009](0009-工作台是焦点引导器.md)、[ADR-0010](0010-焦点资格与排序.md)

## 背景

焦点引导器要在顶部回答两件事：**今天还剩多少可排时间**、**这一件装不装得下**。这些数来自一份容量账：一天里哪些时段能装活、每天必须还清的固定成本有多少、外部插单要预留多少、一个深度块有多长。

这份账此前只存在于一份本地文档里，工作台一个字都没显示。v2 要把它显示在主位，就必须先定清楚三件事：**它从哪来**、**谁来改**、**改了怎么生效**。

## 决定

- **容量参数是本机机读文件**，由**会话里的 agent** 在**初始化流程**中建立，在**周回顾**时提议修订，**用户点头才改**。
- **只存输入，不存推导值**：可排时间由插件用「窗口时长 − 日清成本 − 插入损耗」实时计算，不落配置。
- 工作台**只读**这份配置，并在顶部显示「**参数定于 &lt;日期&gt;**」。
- **公开仓库只提供 schema 与通用默认值**；真实数值属于个人工作容量，不进公开仓库。
- **调参必须经会话确认**，不做自动化改写。

配置形状（决策密集，故内联；示例值为虚构）：

```jsonc
{
  "定于": "YYYY-MM-DD",
  "窗口":   [{ "起": "09:00", "止": "12:00" }, { "起": "13:30", "止": "16:00" }],
  "不可占": [{ "起": "12:00", "止": "13:30", "说明": "午休" }],
  "日清":   [{ "名": "示例固定成本", "时段": "09:00", "成本分": 15 }],
  "插入损耗分钟": 45,
  "深度":   { "单日上限分钟": 180, "单日配额": 1, "估时系数": 2 },
  "番茄分钟": 25
}
```

字段语义：**窗口**是每天真正能装活的那几段工时；**不可占**是从窗口里扣掉的不可支配段；**日清**是当天必须还清的固定成本清单（每条带时段与成本）；**插入损耗分钟**是外部随时占用、无法事先安排的预留；**深度**一组是深度动作的单日上限、单日名额与估时系数。

## 理由

- **参数必须由"知道用户一天怎么过"的会话建立**，而不是由代码里的默认值猜。默认值是通用形状，不是这个人的一天；猜出来的数字比没有数字更危险，因为它看起来是准的。
- **只存输入不存推导值**：推导值会与输入不同步——改了窗口忘了改余量，两处数字就开始打架。实时算则永远只有一份真相。
- **用户点头才改**：容量参数是关于用户生活的判断，不是系统内部旋钮。自动改写等于让系统替用户决定他的一天怎么过。agent 可以提议（周回顾时拿着这一周的实际执行情况说"这次可排时间似乎偏乐观"），但改不改由用户说。
- **工作台只读配置**：工作台不该长成第二个需要维护的地方（[ADR-0006](0006-工作台是只读视图.md) 的"不写本地文件"这条硬护栏在 v2 仍然成立）。参数写口属于会话。
- **显示「参数定于 &lt;日期&gt;」**：顶部那个数是工作台说得最肯定的一句话。让用户看见它多久没校准，比让这个数消失更有用——它是"这个数还准吗"的入口。
- **公开仓库只放 schema 与默认值**：仓库读者能看懂形状、能改代码，但没有看到任何一个人的真实容量。

## 代价

- **首次使用多一道初始化流程**：参数建立之前，工作台给不出剩余时间。必须显示"未设定"（而不是 0、也不是猜的数）——猜的数会被当成准的数用。
- **调参滞后于生活变化**：日程换了而参数没改，顶部数字会开始骗人。"参数定于 &lt;日期&gt;"是缓解手段，不是消除。真正的修复依赖周回顾时有人记得提这件事。
- **工作台上没有参数编辑入口**：要改参数得回到会话。这是有意的，但意味着"改参数"这件事比"勾完成"多绕一圈。
- **参数是本机文件，跨设备不跟随**：同一份参数在另一台机器上不存在，初始化流程得重跑一遍。
- **窗口与日清的时刻粒度是分钟**：写得越细越准，但也把"按天/按周"的使用者逼进更细的记账。默认值应给粗粒度，让初始化流程按实际情况细化。
