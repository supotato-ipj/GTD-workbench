# 像素工位 · 一次性假数据原型（工单 #13）

打开 `prototype/pixel-desk/index.html` 即可（零依赖，双击可用）。

**字体为什么要内联**：从 `file://` 打开时，浏览器按 CORS 规则拒绝加载本地字体文件，
第一版就是因此退回了宋体。所以点阵字体现在是 `font/font.css` 里的 base64 data URI
（Fusion Pixel 12px，OFL 1.1，许可文本在同目录）。真实插件里字体由 Host 路由发出，不需要这层内联。

## 第三版改了什么

- **卡更矮更胖**：200 × 280 美术像素（≈1:1.4），仍然竖着、立在桌面上，底部有投影。
- **桌面抬高**：桌面占画面下方约三分之二（250/420），墙只剩上面三分之一。
- **日清的便签叠压在卡夹下方**，与卡夹同列。
- **时限只留卡上那枚标签**，桌左小屏不再重复；小屏只报 `11-08 周六` / `预计 40 分钟` / `装不下` / `可排 0 分钟`。
- **台灯改成锥形灯罩**，罩口一圈暖色——上一版那几条横条看着不像灯。
- 「等回 2」红标签保留在右下。

## 要回答的观感问题

1. **比例**：200×280 是不是"竖着但不像一张竖着的纸条"？再矮一点（200×260）还是再胖一点（210×280）？
2. **卡上只剩三样**（标题、时限标签、完成要求 + 两个写口），空出来的地方够不够"像一张卡"，还是显得空？
3. **小屏在桌左**：位置对不对、字号会不会太小；它现在承担"这张卡装不装得下"。
4. **光**：卡被照亮、卡夹退到暗处的层级还成不成立。

## 做的取舍

- 场景画在 600×420 的美术网格上，按「1 美术像素 = k 个设备像素」整数放大；卡片文字是真正的 HTML，字号 12／24 美术像素。
- 光用阶梯条带，不用渐变——渐变会糊掉像素边。
- 六箱画布没做：点抽屉或「六箱画布」标牌只弹占位说明。
- 没有写口：完成／改期／跳过／重试只播动画与占位提示，不写任何数据。
- 数据全是编的：季度合规自查表、供应商名录、合同模板页眉、部门周会材料、往来函件归档。

## 怎么玩

- 卡面：完成／改期＝盖章后抽走、下一张滑上来；跳过＝插回卡夹末尾。都是占位。
- 卡夹里的任一张：点一下抽到主位（零写入），左边小屏跟着换。
- 便签叠：点开看"容量参数定于某日""窗口外日清不占可排时间"。
- 「等回 2」：点一下说明它是等待清单里「到期没回」的那几条。
- 桌沿「六箱画布」或抽屉：弹占位说明。
- 键盘 ← → 换卡；左上角控制条切有卡／空态／取数失败。

## 已知的风险

- 标题超过三行会顶到按钮：竖版卡内宽 180 美术像素，长标题折行多。实施时要定规约（截断／缩排／允许卡变高）。
- 便签叠展开时那张说明会伸出叠外——现在是有意为之（像抽出一张便签），位置还要调。
- 卡夹在右侧暗处，只靠纸色被看见；如果觉得太暗，是第一个要调的地方。
- 120%／150% 缩放下字发虚的话，是字号没落在整数设备像素上——原型按 DPR 算了，但没在真机上核过。
